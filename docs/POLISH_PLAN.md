# Komputy front end polish plan: solid surfaces, plain text

Two goals for every screen of komputy.com (marketing site, sign in, the app, the platform console, emails):

1. **Solid surfaces.** Nothing is see-through. A menu, header, sidebar, drawer, dialog, toast or tooltip
   fully covers what is behind it. No glass, no blur, no half-transparent panels.
2. **Plain text, no dashes of any kind.** No em dash, no en dash and no hyphen in the words people read.
   "sign-off" becomes "sign off", "14-day trial" becomes "14 day trial", an empty cell says "Not set".

Component structure, layout, spacing and behaviour stay exactly as they are. Only surface colours and
wording change.

## 2. Solid surfaces: the rules

| Element | New surface |
|---|---|
| Marketing header, app top bar | `bg-canvas`, bottom border `border-line` |
| Sidebar, mobile navigation drawer | `bg-canvas-deep` (dark) / `bg-raised` (light), right border |
| Services mega menu, dropdowns, popovers, command palette, date picker, tour cards | `bg-raised`, `border-line`, existing shadow |
| Dialogs, drawers, confirm sheets | `bg-raised`, `border-line` |
| Toasts | `bg-raised`, `border-line` |
| Sticky bars (save bar, sign off bar, table bulk bar, wizard footers) | `bg-canvas`, top border |
| Chart tooltips | `bg-raised`, `border-line`, no blur |
| Table header and hover rows | `bg-surface` / `bg-surface-hover` (solid tokens that already exist) |
| Status tints | new solid tint tokens (`--accent-tint`, `--positive-tint`, `--warning-tint` solid in both themes) |
| Backdrop behind dialogs (`--scrim`) | solid dimming colour with **no blur**; see decision D1 |

Implementation, in this order:

1. **Tokens.** In `globals.css`, `--overlay` becomes a solid colour in both themes; add solid
   `--*-tint` values; delete the `.glass` utility and its `backdrop-filter`.
2. **Replace every `glass` class** (25 uses) with the matching solid surface from the table, one component at a
   time, keeping the existing border, radius, shadow and spacing.
3. **Replace every translucent fill** (`/30` to `/95` on canvas, surface, raised) with the solid token.
4. **Remove `backdrop-blur`** from the charts and the command palette; **delete `ProgressiveBlur`** and its uses.
5. **Guard.** A CI check fails on `glass`, `backdrop-blur`, `backdrop-filter` or a slash opacity on a
   surface colour (`bg-(canvas|surface|raised|overlay)/NN`).
6. **Visual check** in both themes and at phone, tablet and desktop width: Services menu over the hero, header
   over scrolled content, sidebar and mobile drawer, every dialog, toast, command palette, tour, date picker,
   chart tooltip, sticky bars over long tables.

Decorative background art that sits *behind* content (the hero gradient images and the soft colour glows in
the landing page) is not an overlay and stays, unless you want it gone too (decision D2).

## 3. Plain text: the rules

### 3.1 Wording (one glossary, used everywhere)

| Was | Becomes |
|---|---|
| sign-off (noun), sign-off date | sign off, approval; sign off date |
| signed-off | signed off |
| sign-in, sign-up, sign-out (nouns) | sign in, sign up, sign out |
| 14-day trial, 30-day, 6-digit | 14 day trial, 30 day, 6 digit |
| read-only | view only |
| month-end, quarter-end | month end, quarter end |
| roll-forward | roll forward |
| maker-checker | maker and checker approval |
| short-term, low-value | short term, low value |
| non-current, non-lease | non current, non lease |
| day-count, cut-off, opt-in, two-step | day count, cutoff, opt in, two step |
| loan-level, money-weighted, collateral-aware, month-by-month | loan level, money weighted, collateral aware, month by month |
| plain-English, watermark-free, SSO-ready, self-serve, multi-entity, multi-tenant, add-ons, pre-filled, time-boxed, breach-checked, high-volume, rent-free | plain English, no watermark, ready for SSO, self service, multi entity, multitenant, add ons, prefilled, time limited, checked against breaches, high volume, rent free |
| Coming-soon (label) | Coming soon |
| AES-256, TLS 1.2+ | AES 256, TLS 1.2 or later |
| PD-01, EC-12 (rule codes) | PD 01, EC 12 |

### 3.2 Empty values

A small `Empty` atom replaces all 51 `-` placeholders: it renders muted text with the word that fits the
column (`Not set` for fields, `None` for lists and people, `Not yet` for dates still to come, `No data` in
numeric tables) and keeps the cell's alignment. Screen readers hear the same word.

### 3.3 Numbers, ranges and dates

| Case | Rule |
|---|---|
| Ranges | "Jan to Sep 2026", "1 to 50 employees", "IFRS 16.53 to 58" |
| Negative amounts | accounting style in parentheses: (1,234.56), as finance teams expect; percentages: "down 38 %" |
| Dates shown to people | always written out: "15 Nov 2026", never 2026-11-15 |
| Time spans | "10:02 to 11:40" |

### 3.4 Codes and customer data

| Case | Rule |
|---|---|
| Komputy record codes (RUN-0142, LSE-0087, REQ-...) | decision D3 |
| Customer data (loan IDs, customer IDs, file names inside uploads) | shown exactly as the bank sent it; we never rewrite a client's identifiers |
| Email addresses and URLs (no-reply@komputy.com) | unchanged (technical, not prose) |

### 3.5 Where it applies

Every string a person reads: page text, headings, buttons, labels, placeholders, tooltips, toasts, empty
states, validation messages (web and engine), emails, notification titles, PDF/Excel report text, metadata,
share card, RSS, legal pages, mock and seed data shown in demos.

### 3.6 Guard

A test renders the public pages and the main app screens (seeded demo workspace) and fails if visible text
contains a dash between two letters or a dash used as a word, with an allowlist only for customer data and
emails. It runs in CI with the e2e suites.

## 4. Order of work and checks

| Step | Work | Check |
|---|---|---|
| P1 | Tokens and `.glass` removal (section 2, steps 1 to 4) | Typecheck, build; screenshots of every overlay in both themes and three widths |
| P2 | Surface guard in CI | CI passes |
| P3 | Glossary pass over web text and engine messages | Text scan of rendered pages shows zero hyphenated words outside the allowlist |
| P4 | `Empty` atom replaces the 51 placeholders | Screens with empty fields read naturally |
| P5 | Ranges, negatives, dates | Report and journal screens checked against a seeded run |
| P6 | Codes per decision D3 | e2e suites pass |
| P7 | Text guard in CI | CI passes |
| P8 | Deploy, then the same checks on komputy.com | Screenshots attached to the report |

## 5. Decisions (my defaults; say if you want any changed)

| # | Question | Default |
|---|---|---|
| D1 | Backdrop behind dialogs: a solid dark colour (page hidden) or a solid dimming layer without blur (page faintly visible, the usual pattern) | **Solid panels everywhere, dimming layer without blur behind dialogs**, darkened to 80 % so the page behind is not readable |
| D2 | Decorative glows and gradient art behind the hero | **Keep** (they are background, not overlays) |
| D3 | Komputy record codes such as RUN-0142 | **RUN 0142** in text, generated without the hyphen from now on; old codes are still found when typed either way |
| D4 | "read-only" | **view only** |
